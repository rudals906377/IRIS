# 작업 인수인계 (다음 세션용)

작성: 2026-09-29(2차 세션에서 갱신). 이 문서는 새 세션이 이 프로젝트를 이어받아 **나이키·아디다스 공식 홈페이지 기준으로 완성**하기 위한 것이다.

## 1. 사용자와 약속된 방식

- **모든 대화·진행 안내·문서·커밋 메시지는 한국어**로 쓴다. 영어는 기술 용어에만 쓴다.
- 사용자는 이 분야를 잘 모르며 "알아서 해 달라"고 했다. 결정은 스스로 내리고, 사용자 손이 꼭 필요한 일(맥북에서 직접 써 보기, 설정 한 번 바꾸기)만 짧고 쉽게 요청한다.
- 목표는 "최고의 결과물". 교수님 평가는 경험 위주라 기술 선택은 자유.
- 방향(2026-09-30 확정): 팀 공통 주제였던 AnyDoor는 쓰지 않는다(교수님: 더 좋은 모델·방식을 찾으면 그것을 써도 됨). IRIS의 실시간 방식(브라우저 안 추적 + 마스크 합성)을 중심으로 빨리 완성하고, 남은 기간은 완성도를 끌어올린다. 고화질 사진 한 장 모드가 필요해지면 옷 전용 모델(CatVTON, IDM-VTON 등)을 사용자 NVIDIA PC에서 돌리는 방안을 검토한다.
- 조건: MacBook Air M5 16GB, 윈도우 NVIDIA GPU PC 있음(필요 시), 추가 예산 없음(유료 서버·클라우드 불가), 1인 개발, 결과물은 **공개 웹 + 크롬 확장 프로그램**.
- 공개 저장소이므로 **나이키·아디다스 상품 사진 파일은 절대 커밋하지 않는다**(저작권). 시험용 사진은 `web/public/testdata/`(gitignore)에만 둔다.

## 2. 지금까지 된 것

| 영역 | 상태 |
|---|---|
| 실시간 착용 엔진(상의) | 브라우저 안에서 MediaPipe 자세·분할 → 신체 좌표계 → 몸판·소매 변형 → WebGL 합성. 영상은 기기 밖으로 안 나감. **2일차 개편:** 몸통을 타원 기둥으로 보고 매 줄 옆선을 분할에서 잰 착용자 윤곽(지금 입은 옷 가장자리)에 맞춤(`silhouette.ts`), 몸통 회전 추정(`body.turn`)으로 먼 쪽 압축·뒷면(원단 바탕색), 소매는 관 좌표(`buildTube`)로 팔 두께에 맞춤, 어깨점은 착용자 팔 위(드롭숄더 반영) |
| 원래 옷 지우기·목 보존 | 새 옷에 덮이지 않은 원래 옷(후드 모자·긴 소매·밑단)을 배경 기억·주변 배경·피부 평균색으로 지움(`CAMERA_FS`의 uRemove). 어깨선 위 피부(목)는 어떤 부위도 덮지 않되, 깃이 높은 옷(`highNeck`: 목폴라·하이넥·폴로·재킷 깃)은 예외 |
| 마스크 합성 | 교체(옷), 보존(얼굴·머리카락·배경), 가림(손·팔), 목 안쪽(뒷깃) 부위, 가이디드 필터로 머리카락 올 단위 경계 |
| 착용 품질 | 가로·세로 배율 분리, 소매 4꼭짓점 곡면 모델(진동 둘레에 붙고 팔 바깥·안쪽 선을 따라감, 긴팔은 팔꿈치에서 굽음), 원래 옷 주름 음영 전이(인쇄 무늬는 걸러냄) |
| 측정 | 단계별 처리 시간, 촬영→그리기 지연, 건너뛴 프레임, 1분 추세, 거울 루프백 지연 측정, JSON 내보내기 |
| 상품 사진 자동 분석 | 배경 제거(경계 기반 flood fill, 균일 배경이면 좁은 색 범위 + 경로 기준색으로 흰 옷 보호) + 윤곽 분석(겨드랑이 = 볼록 껍질 틈의 가장 깊은 곳, 늘어뜨린 소매는 비율 추정, 후드 모자·열린 앞판·늘어진 끈 처리) + 비율 검증. 시험 사진 21장 중 16장 신뢰도 0.6 이상(나머지는 민소매·보디수트 등 의도된 거절 포함) |
| 모델 착용 사진 | 자세 추정 + 다중 클래스 분할 '옷' 영역 → 하의와의 색 경계로 밑단, 팔 선으로 소매 → 가로 배율 보정(`widthScale`) 후 착용. `analyze/worn.ts` |
| 크롬 확장 프로그램 | v0.2.0. 후보 수집(og:image, JSON-LD, 지연 로딩·picture, 추천 상품 제외, 아디다스 파일명 규칙) → 나이키·아디다스 고해상도 주소 변환(`extension/urls.ts`) → 착용 창이 후보를 빠르게 평가해 옷 사진 자동 선택 → 없으면 모델 착용 사진 분석. 나이키형·아디다스형·모델 사진만 있는 시험 페이지로 전체 흐름 확인. **실제 두 사이트는 이 세션 환경에서 접속이 막혀 미확인** |
| 배포 | GitHub Actions → Pages. **사용자가 Settings → Pages → Source를 "GitHub Actions"로 바꿔야 첫 배포 성공**(아직 미확인) |

## 3. 구조

```
web/src/engine/
  engine.ts      전체 흐름(프레임마다 추적→변형→합성→측정), setProduct/setAsset
  tracker.ts     MediaPipe Pose + 다중 클래스 분할(확률 마스크) + 손(선택)
  body.ts        관절점 → 신체 좌표계(One Euro 필터, 추적 손실 시 서서히 사라짐)
  rig-top.ts     상의 변형(몸판: 타원 기둥 + 착용자 윤곽, 소매: 관 좌표 + 바깥선/안쪽선) — 핵심 로직
  silhouette.ts  분할에서 몸통 반폭·팔 반두께 측정(TorsoTracker, 시간 평활)
  occluders.ts   팔·손 캡슐(R 팔 중심, G 팔 주변 피부 판정, B 손)
  renderer.ts / shaders.ts   WebGL2 합성, 가이디드 필터, 디버그 표시
  garment.ts     상품 자산(이미지·라벨·기준점) → 부위별 격자 메쉬
  analyze/       상품 사진 자동 분석(background.ts 배경 제거, top.ts 옷만 찍힌 사진, worn.ts 모델 착용 사진, index.ts 흐름)
web/src/app/main.ts   화면·설정·확장 프로그램 후보 목록·사진 업로드
web/extension/        manifest.json, background.ts(서비스 워커·후보 수집), urls.ts(고해상도 주소 규칙), icons
tools/garments/       자체 제작 상품 이미지 생성기(파이썬)
tools/harness/        헤드리스 시험 도구(README 참고)
tools/analyze/        상품 사진 분석 결과표 도구(README 참고)
docs/research/        나이키·아디다스 페이지·이미지 주소 조사
```

부위 라벨 번호: 1 몸판, 2 착용자 왼쪽 소매(사진 오른쪽), 3 오른쪽 소매, 4 목 안쪽. 기준점 이름의 L/R은 **착용자 기준**.

## 4. 개발·시험 명령

```bash
cd web && npm ci && npm test && npm run build          # 단위 테스트, 사이트 빌드(dist/)
npm run build:ext                                       # 확장 프로그램(dist-ext/) + release/iris-extension.zip
npx vite preview --port 4173 &                          # 시험 서버
bash tools/harness/fetch-testdata.sh                    # 시험 자료
cd tools/harness && npm install                         # playwright
```

`tools/harness/README.md`, `tools/analyze/README.md`에 사용법이 있다. 헤드리스 크롬은 GPU가 없어 느리므로 **속도 판단은 하지 말고 모양만** 본다.

## 5. 다음 세션이 할 일 (우선순위 순)

2차 세션에서 한 일: 분석 정확도 개선(겨드랑이·흰 옷·후드·열린 재킷·끈), 확장 프로그램 후보 수집·자동 선택·고해상도 주소, 모델 착용 사진 지원, 시험 쇼핑몰(`tools/harness/fake-shop.mjs`)과 분석 결과 그림 도구(`asset.mjs`), 조사 문서 `docs/research/nike-adidas.md`.
**이 세션의 클라우드 환경은 나이키·아디다스 접속이 네트워크 정책으로 막혀 있었다**(프록시 403). 그래서 아래 1~2가 남았다.

1. **실제 사이트 확인**(접속 허용 필요: 환경 설정 → Network access에 `www.nike.com`, `static.nike.com`, `www.adidas.co.kr`, `assets.adidas.com`):
   - `node tools/harness/ext.mjs <상세페이지>`로 두 사이트 상의 10개씩 → 후보 목록·`selected`·`fit` 확인
   - `urls.ts`의 고해상도 변환이 404 나는지, 옷만 찍힌 사진이 후보에 들어오는지 확인 후 `docs/research/nike-adidas.md`에 실측 결과 기록
2. **실제 상품 사진 20장 이상으로 분석 결과표**(`tools/analyze`) → 나이키 연회색 배경 흰 옷, 아디다스 laydown 후드·재킷 실패 유형 개선
3. 모델 착용 사진: 늘어뜨린 긴소매가 손목 쪽에서 바깥으로 벌어져 보임(소매 끝 기준점을 팔 방향으로 정렬하면 개선 여지), 팔이 몸 앞을 가린 사진 처리
4. 하의·모자(설계 문서 참고)

## 6. 알려진 문제·아이디어

- 2일차 개편 뒤 남은 것: 소매 뿌리·겨드랑이 부근 작은 틈, 원래 옷 지운 자리의 피부색 채움이 덩어리로 보임(팔 캡슐 밖), 몸을 돌릴 때 옆선 부근 이음새, 상반신 구도(엉덩이 안 보임)에서는 회전 각도를 깊이(z)로만 추정해 흔들림. 시험용 설정 `forceTurn`, `debugRemove`, `debugRemoveFill`, `debugGarment`(1 라벨, 5 소매만)로 확인.
- 지퍼 옷은 사진에 찍힌 상태(열림/잠김) 그대로 입힌다. 열린 앞판 틈으로는 착용자 자신의 옷이 보인다(의도).

- 겨드랑이 근처에 원래 옷이 가늘게 보이는 틈이 가끔 남음(팔 캡슐 반경·소매 안쪽 폭 조정 여지).
- 민소매·보디수트·끈 달린 옷은 자동 분석이 거절됨(의도). 민소매 겨드랑이 검출은 개선 여지.
- 하의·모자·장갑은 아직 없음(`docs/realtime-virtual-try-on-plan.md`의 설계 참고, 순서: 모자 → 하의 → 장갑).
- 실제 기기 지연 측정 결과가 아직 없음. 사용자가 맥북에서 **측정 → 설정 → 거울 루프백 측정**을 해 주면 판단 가능.
- 확장 프로그램 `background.ts`의 `irisTest`는 자동 시험용 훅(사용자 기능 영향 없음).
