# 작업 인수인계 (다음 세션용)

작성: 2026-09-30(주제 변경 후 갱신). 새 세션이 IRIS **가상 뷰티**를 이어받아 완성하기 위한 문서다.

## 1. 사용자와 약속된 방식

- **모든 대화·진행 안내·문서·커밋 메시지는 한국어**로 쓴다. 영어는 기술 용어에만 쓴다.
- 사용자는 이 분야를 잘 모르며 "알아서 해 달라"고 했다. 결정은 스스로 내리고, 사용자 손이 꼭 필요한 일(맥북에서 직접 써 보기, 설정 한 번 바꾸기)만 짧고 쉽게 요청한다.
- 목표는 "최고의 결과물". 빨리 완성하고 남은 두 달은 완성도를 끌어올린다. AnyDoor는 쓰지 않는다(교수님: 더 좋은 모델·방식을 써도 됨).
- **주제 변경(2026-09-30)**: 옷 입어 보기는 AnyWear라는 기존 프로그램이 있어 접고, **헤어·네일아트·메이크업·타투**로 바꿨다. 옷 관련 코드(착용 변형, 상품 사진 분석, 크롬 확장, 상품 이미지)는 모두 지웠고, 카메라·측정·MediaPipe 추적·WebGL 합성·가이디드 필터는 다시 썼다. 지난 코드는 git 기록에 남아 있다.
- 조건: MacBook Air M5 16GB, 윈도우 NVIDIA GPU PC 있음(필요 시), 추가 예산 없음, 1인 개발, 결과물은 공개 웹.
- 공개 저장소이므로 저작권 있는 사진·영상은 커밋하지 않는다. 시험 자료는 `web/public/testdata/`(gitignore)에만 둔다.
- 개발일지는 하루가 끝날 때 `docs/devlog/`에 쓴다(예약 작업 "IRIS 개발일지 기록", 매일 22:50 한국 시간).

## 2. 지금까지 된 것

| 영역 | 상태 |
|---|---|
| 추적 | MediaPipe 얼굴 점 478개(Face Landmarker), 다중 클래스 분할(R 머리카락, G 몸 피부, B 얼굴 피부, A 사람), 손·자세는 선택. 얼굴 점 떨림 억제는 **2단 필터**(`face.ts`): 머리 전체 움직임(Procrustes 닮음 변환: 이동·회전·크기)과 얼굴 안 모양(표정)을 나눠 각각 변위 적응 필터(차이가 잡음 수준이면 강하게, 크면 바로 따라감, 기준은 얼굴 폭 비례)로 거름. 합성 영상 측정(`tools/harness/jitter/`): 빠른 흔들기 오차 16.7 → 4.2px, 정지 떨림 0.18 → 0.06px, 말할 때 입술 오차 3.0 → 1.2px. 놓치면 150ms 유지 후 서서히 사라짐. 손 점도 같은 필터(`RigidShapeFilter`, 손바닥 기준), 손 필터는 왼/오른손 판정이 아니라 **위치로 짝지음**(판정이 뒤바뀌어도 안 튐) |

| 윤곽 | 쉐딩(광대 아래 선 띠, 턱선·관자놀이는 윤곽에서 안쪽으로 옅어지는 띠, 코 옆 선)과 하이라이터(콧대 선, 광대 위·인중 위·턱 끝·이마 타원)를 세 번째 마스크(m3 R·G)에. 쉐딩은 피부×색 비율, 하이라이터는 빛 받는 곳(명암>1)일수록 밝게. 얼굴 피부(분할 B)에만 |
| 피부 보정 | 얼굴 피부(분할 B) − 이목구비(눈·눈썹·입술 다각형). 반 해상도 카메라 흐림(얼굴 둘레만 scissor) 대비 작은 결만 30%로 줄임(큰 경계 유지) → 볼 평균색 쪽으로 30% 톤 정리 → 호수 색 비율 35% |
| 헤어 컬러 | 머리카락 확률(가이디드 필터) → 64×64 통계 텍스처 밉맵으로 평균·분산 → 상대 밝기로 목표색 조절, 밝은 결은 채도 낮춤, 경계는 상대 밝기를 1로 눌러 테두리 번쩍임 방지, 옴브레(얼굴 점으로 뿌리·끝 위치) |
| 타투 | 자세 추적(타투를 켤 때만 켬) + 얼굴 턱선 보조점 → 부위 축 → 격자(팔은 원기둥: 화면 오프셋 R·sinθ, 보임 cosθ). 분할 G로 팔 굵기 측정·평활. 피부(G, 가까운 목은 B도)에만 곱하기 잉크. 가로로 긴 도안은 팔 방향으로 회전. 도안은 Path2D 선화 7종 + 사진 올리기(밝은 바탕 자동 제거) |
| 네일(2차) | 손 추적(네일을 켤 때만) → 손가락 끝 마디 위 손톱 사각형 → 둥근 사각형 모양·광택·무늬. 손등 방향 부호는 시험 영상으로 확인('Right' 손은 손등일 때 양수). 피부가 보이는 곳에만 칠함. 2차: 손가락 피부 기준점(마지막 마디 뒤) 밝기와 비교해 추정 손톱 가장자리를 넓히거나 줄임(안쪽은 늘 칠함). **한계**: 손 점이 손톱 경계를 모르므로 네모나게 보이고 위치가 어긋남, 물건 아래로 접힌 손가락을 모델이 편 손가락으로 추정 |
| 사진 따라하기 | 사진 분석(photo-style) → 측정(face-measure: 2차식 피부 흐름 대비 비율) → 역산(style-math) → 적용 → 되먹임(style-match, captureNext로 합성 화면을 읽어 3회) → 스타일 AI 힌트(style-ai/style-attributes, 별도 저장소 분류기를 jsDelivr 커밋 고정으로 불러옴, importmap으로 Transformers.js 연결) |
| 생성 모드 | `tools/genserver`(FastAPI). 마스크: 헤어 = 머리카락 분할 + 머리 크기×grow 넓힘 − 얼굴·몸 피부, 네일 = 손 점 → 손톱 사각형, 타투 = 자세 점 캡슐 ∩ 피부. 생성: SD1.5 인페인팅(`stable-diffusion-v1-5/stable-diffusion-inpainting`) + IP-Adapter(h94, sd15), 마스크 안만 합성. `--dry-run`은 영역만 표시. 웹은 `gen-mode.ts`, 설명(prompt)은 스타일 AI 속성의 영어(label_en) |
| 화면 | 아래 탭(룩/피부/립/아이섀도/블러셔/윤곽/아이라이너/눈썹/헤어/네일/타투), 색 견본 + 직접 고르기, 농도·광택·입술 라인·펄 슬라이더, 립 모양 선택, 룩 7종 |
| 측정 | 단계별 처리 시간(얼굴·분할·자세·효과·그리기), 촬영→그리기 지연, 거울 루프백, JSON 내보내기 |
| 배포 | GitHub Actions → Pages. 사용자가 Settings → Pages → Source를 "GitHub Actions"로 바꿔야 첫 배포 성공(아직 미확인) |

## 4. 개발·시험 명령

```bash
cd web && npm ci && npm test && npm run build          # 단위 테스트, 사이트 빌드(dist/)
npx vite preview --port 4173 &                          # 시험 서버
bash tools/harness/fetch-testdata.sh                    # 시험 자료(얼굴 확대 영상 포함)
cd tools/harness && npm install                         # playwright
```

헤드리스 크롬은 GPU가 없어 느리므로 **속도 판단은 하지 말고 모양만** 본다.

**점수로 확인(2026-10-08~)**: 정확성·자연스러움을 바꾸는 변경은 [tools/eval](../tools/eval/README.md)로 전후 점수를 잰다.
머리카락 영역(`hair.mjs`, 웹캠형 25장·떨림), 염색 색·결(`haircolor.mjs`, 실제 머리 사진 32장 분포), 사진 따라하기 색(`makeup.mjs`, 21장).
평가 중에는 빌드하지 말 것(dist/testdata 가 지워져 평가가 멈춘다). H.264(mp4)는 헤드리스 크로미움이 못 틀어서 평가 영상은 VP8 webm 으로 바꿔 둔다.
커밋 전에 `node tools/harness/smoke.mjs`(모든 효과를 켜고 셰이더 컴파일 오류 확인)를 돌린다. 색 변경은 여러 피부 톤 시험 영상(00035·00121은 어두운 톤)에서 함께 확인한다.

0. **과제(AnyDoor) 연동 — 2026-10-03**: 과제 핵심은 "참고 사진의 물체를 내 사진의 지정 자리에 합성"(AnyDoor, ali-vilab, MIT). ✨ 생성 모드의 엔진으로 붙였다.
   `tools/anydoor/`(공식 저장소 래퍼 `anydoor_server.py` 8766, `setup.py`(.bat 은 한 줄 래퍼) 로 전용 venv·torch 2.0.1 cu118·가중치(축약본 4.9GB + DINOv2 4.5GB)·설정 경로), 생성 서버 `engine: anydoor`(`anydoor_client.py`: 참고 물체 마스크 추정 — 헤어 분할/손톱/잉크, 대상 자리 — 헤어 마스크/손톱마다/팔 가운데 비율 상자), 웹 ✨ 패널 엔진 선택.

   ①은 `tools/train/hair/`(prepare.py: CelebAMask-HQ + ViTMatte/BiRefNet 정밀화, train.py: 0.4M 경량 U-Net) 완성. 2차 학습본(CelebAMask 2,092장 + 시험 영상 웹캠 풍 프레임 90장 자동 라벨, 1차 가중치에서 CPU 9회 이어 학습, 검증 MAD 6.6%; 시험 영상 4개에서 범용 분할·1차보다 경계가 깨끗)을 `web/public/models/hair-matte-256.onnx`로 커밋(1차는 1,425장·MAD 7.4%), 설정 체크박스 '자체 학습 머리카락 모델'로 켠다. 시험 영상에서 범용 분할과 동급(아직 우위 아님). 다음: 학교 GPU에서 전체 데이터(--shards 6 --test) + 사용자 웹캠 사진(--webcam)으로 재학습, 384 입력 모델로 교체.

1. **생성 모드 실사용 확인(방향 (a): 내 컴퓨터 GPU 서버로 확정)**: 시험 PC는 윈도우, RTX 3080 10GB, RAM 32GB(기본 설정 그대로 가능, SDXL도 fp16으로 가능한 사양). 사용자가 학교 GPU PC에서 `tools/genserver/setup.py` → `run.bat` → README의 "실행과 첫 생성" 순서대로 시험 → 헤어·네일·타투 결과 품질 확인. 헤어는 마스크가 넓어 옷·배경이 바뀔 수 있음(grow 줄이기, 또는 옷 분할을 마스크에서 빼는 옵션). 품질이 부족하면 SDXL 인페인팅 + IP-Adapter-plus, 헤어 전용(Stable-Hair) 검토
2. **사진 따라하기 잔여 오차(21장 회귀, 2026-10-02 저녁)**: 립 평균 0.002. 블러셔·섀도 색조 오차 평균 0.05~0.08. 튀는 것: 04(사과존만 바른 사진인데 결과는 볼 가운데까지 분홍, B 채널 과함 1.17 vs 1.02), 16(섀도 B 채널 결과 1.0 vs 사진 0.8 — matchTint가 주도 채널(R)만 맞추고 B는 못 내림), 13·05(섀도 안쪽 약간 약함). 되먹임에서 주도 채널 외 채널도 함께 맞추는 개선 여지
2. **손톱 자동 라벨은 실패**: Mixkit 손 영상(손 겹침·옆면)에서 손 점이 엇나가 SAM 마스크가 엉뚱한 곳을 잡음(388개 중 쓸 만한 것 거의 없음). `autolabel.py`는 사용자의 깨끗한 웹캠 손 사진에서 초안용으로만. 실제 라벨 필수
2. **실제 웹캠 재확인**: 머리 주변 재분할(headSeg)·GF 1/2 해상도의 속도 영향(HUD 분할 ms), 손톱 위치(엄지·소지)는 실제 카메라 스크린샷으로 다시 맞춘다. 사용자 스크린샷 기반 시험 영상(`testdata/user/`)은 효과가 이미 입혀져 있어 위치 확인용으로만 쓸 것
2. **사진 따라하기 다듬기**: 분류기 저장소가 main에 합쳐지면 `style-ai.ts`의 AI_COMMIT을 갱신. 아이섀도 종류·아이라인 유무는 측정만으로 불확실해 AI 힌트에 의존(힌트 기준 0.4). 광대 위치 블러셔는 자동 판정에서 뺐음(머리카락 섞임). 실제 웹캠에서 되먹임이 조명 변화에 튀지 않는지 확인 필요
2. **네일아트 다듬기**: 두 손이 겹치면 손 모델이 한 손으로 합쳐 보는 문제, 물건 아래 접힌 손가락, 손톱 끝이 뾰족해 보이는 모양. 실제 웹캠(초당 30프레임)에서 확인 필요. 시험 영상: `testdata/hands/`(Mixkit 무료 영상, 커밋 안 함)
2. 헤어·타투 다듬기(타투: 손등·다리 위치, 컬러 잉크, 팔 비틀림)(선명한 원색 염색이 어두운 머리에서 조금 평평해 보임). 메이크업은 오버립·펄·피부 보정·먼 쪽 옅게까지 완료 — 남은 것: 립 두 가지 색(안쪽·바깥 색 따로), 실제 웹캠에서 떨림·조명 변화 확인
3. 실제 기기(맥북)에서 속도·지연 측정

## 6. 알려진 문제·아이디어

- **주의(버그 재발 방지)**: WebGL의 ARRAY_BUFFER 연결은 VAO에 저장되지 않는다. 효과 모듈이 `bufferData` 하기 전에 반드시 자기 버퍼를 `bindBuffer` 할 것(타투·네일 추가 후 메이크업이 통째로 안 그려지던 원인).
- 조명 추정의 기준 피부색은 하나라서, 아주 어두운 피부는 "어두운 조명"으로 일부 오인해 립 색이 조금 어둡게 나올 수 있다(밝기 적응을 0.6제곱으로 약하게 둔 이유). 어두운 톤 시험 사진 2장에서는 자연스러웠음.
- 피부 보정의 호수 색은 색감(언더톤)만 따르고 밝기는 ±8%로 제한(밝은 호수를 어두운 피부에 그대로 곱하면 잿빛으로 들뜸). 룩 기본값은 '톤 유지'.

- 시험 사진의 얼굴이 작으면(얼굴 폭 100px 안팎) 아이라인이 거의 안 보인다(선 두께가 얼굴 폭 비례라 의도된 동작).
- 타투는 거울 모드에서 좌우가 바뀌어 보인다(실제 거울과 같음). 레터링도 거울에서는 뒤집혀 보인다.
- 헤어 스타일(길이·모양) 바꾸기는 생성형 AI가 필요해 실시간으로는 어렵다. 사진 한 장 모드로 NVIDIA PC에서 돌리는 방안을 검토.
