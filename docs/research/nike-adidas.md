# 나이키·아디다스 상세페이지 구조와 확장 프로그램 대응

작성: 2026-09-29

> **확인 상태(2026-09-30 갱신):** 네트워크 허용 후 실제로 확인했다.
> - 나이키: 상의 14개 상세페이지를 받아 갤러리 구조·사진 주소·고해상도 변환을 확인했고, 확장 프로그램 전체 흐름(후보 수집 → 1728px 변환 → 모델 사진 분석 → 착용)을 실제 상세페이지에서 시험했다.
> - 아디다스: `www.adidas.co.kr`은 클라우드 서버 주소에서 오는 자동 접속을 보안 시스템이 403으로 막는다(헤드리스·화면 있는 크롬 모두). 목록 페이지 한 장에서 얻은 실제 사진 주소로 파일명 규칙과 `assets.adidas.com` 고해상도 변환(`w_1200`)만 확인했다. 상세페이지 구조는 사용자 맥북 크롬에서 확인이 필요하다.

## 1. 이미지 CDN 주소 규칙

### 나이키 (`static.nike.com`)

```
https://static.nike.com/a/images/<변환 인자…>/<이미지 id>/<파일명>.png|jpg
  예) /a/images/t_web_pdp_535_v2/f_auto/<uuid>/M+NK+DF+TEE.png
      /a/images/t_PDP_864_v1/f_auto,q_auto:eco/<uuid>/...
      /a/images/c_limit,w_592,f_auto/t_product_v1/<uuid>/...
```

- 변환 인자는 1~2개 경로 조각이며, 마지막 두 조각(`<이미지 id>/<파일명>`)이 사진을 가리킨다.
- 고해상도: 변환 부분을 `t_PDP_1728_v1/f_auto,q_auto:eco` 로 바꾼다(`web/extension/urls.ts`).
- 바꾼 주소가 열리지 않으면 착용 창이 원래 주소로 다시 받는다(`alts`).
- 파일명에 사진 종류(앞/뒤/모델) 정보가 없다. → 착용 창의 사진 분석으로 고른다.
- **실측:** 실제 주소는 `/a/images/t_default/u_<배경 레이어 id>,c_scale,fl_relative,w_1.0,h_1.0,fl_layer_apply/<이미지 id>/<파일명>.png`처럼
  배경 합성 단계(`u_…,fl_layer_apply`)가 들어 있다. `t_PDP_1728_v1/f_auto,q_auto:eco/<이미지 id>/<파일명>`으로 바꾸면 1728×2160 사진이 온다(배경 #EDEDEA 계열 사진 그대로).
- 상세페이지 데이터(`__NEXT_DATA__` → `props.pageProps.selectedProduct.contentImages`)에 선택한 색상의 갤러리가 순서대로 있다(`cardType` image/video).
  `colorwayImages`는 색상별 대표 사진. `og:image`는 갤러리 첫 사진. JSON-LD는 `ProductGroup`이며 사진 목록이 없다.
- **상의 14개 모두 갤러리가 모델 착용 사진뿐**이었다(옷만 찍힌 사진 없음). 순서는 대체로
  ① 정면 상반신 ② 뒷모습 ③ 얼굴·옆모습 확대 ④ 정면 전신 ⑤ 뒷모습 전신 ⑥ 원단 확대, 가끔 동영상 카드.
  → 나이키는 ① 정면 상반신 사진을 모델 착용 사진 분석으로 입히는 것이 기본 경로다.

### 아디다스 (`assets.adidas.com`)

```
https://assets.adidas.com/images/<변환 인자>/<해시>_9366/<상품명>_<색>_<품번>_<번호>_<종류>.jpg
  예) /images/w_600,f_auto,q_auto/…/Tee_Black_IA4845_01_laydown.jpg
      /images/h_840,f_auto,q_auto,fl_lossy,c_fill,g_auto/…/…_21_model.jpg
```

- **실측 파일명(목록 페이지):** `…_000_plp_model.jpg`(모델), `…_00_plp_standard.jpg`(상품만), `…_HM1.jpg`(마우스 올릴 때 모델 사진). `w_1200` 변환 확인(1200×1200).
- 파일명 끝의 종류(상세페이지, 알려진 규칙·미확인): `_laydown`(바닥에 펼친 옷만 찍은 사진), `_standard`, `_model`/`_hover_model`(모델 착용), `_detail`(부분 확대).
  번호 `01`이 앞면, `02`가 뒷면인 경우가 많다.
- 고해상도: 변환 부분을 `w_1200,f_auto,q_auto` 로 바꾼다.
- 후보 순서 가중치: `_laydown` ×3, `_standard` ×2, 앞면(`_01_`) ×2, 뒷면(`_02_`) ×0.5, 모델(`_model`, `_HM1`) ×0.6, 부분 확대 ×0.2.

## 2. 상세페이지에서 사진을 찾는 경로(두 사이트 공통으로 대응)

| 경로 | 설명 | 점수 |
|---|---|---|
| `og:image` | 대표 사진. 두 사이트 모두 첫 갤러리 사진(모델 착용인 경우가 많음) | 가장 높음 |
| JSON-LD `Product.image` | 구조화 데이터의 상품 사진 목록(순서 유지) | 높음 |
| 갤러리 `<img>`·`<picture><source>` | `srcset`·`data-src`·`data-srcset`까지 읽어 지연 로딩 사진도 수집, 가장 큰 후보 | 화면 면적 |
| 갤러리 썸네일 | 작게 보여도 원본이 크거나 알려진 CDN이면 수집 | 낮음 |
| 제외 | `header`·`nav`·`footer`, **다른 상품으로 가는 링크 안**(추천·최근 본 상품), 화면 2.5배 아래 | — |

같은 사진의 다른 크기 변형은 CDN 주소의 마지막 두 조각으로 묶어 한 번만 넣는다.

## 3. 착용 창의 자동 선택

1. 후보를 앞에서부터 최대 8장 받아 **빠른 평가**(규칙 방식 배경 제거 + 상의 형태 분석, 모델 불필요)를 한다.
   배경이 단색이 아니면(연출·모델 사진) 점수를 깎는다.
2. 신뢰도 0.75 이상인 첫 사진에서 멈춘다(앞순위 = 대표·앞면 우선, 뒷면 laydown보다 앞면).
3. 옷만 찍힌 사진이 없으면(신뢰도 0.45 미만) 대표 사진을 **모델 착용 사진 분석**으로 넘긴다.
4. 목록 타일에 "옷 사진" 표시, 모델·연출 사진은 흐리게 표시한다.

## 4. 모델 착용 사진 분석(`web/src/engine/analyze/worn.ts`)

- 자세 추정(Pose, 정지 사진 모드)으로 어깨·팔꿈치·손목·엉덩이 관절점을 찾고, 다중 클래스 분할의 '옷' 영역을 쓴다.
- 상체와 팔 부분만 잘라 분할 해상도를 높인다. 피부가 보이지 않으면(옷만 찍힌 사진의 자세 오검출) 쓰지 않는다.
- 밑단: 엉덩이 근처 가운데 띠에서 위아래 색 차이가 가장 큰 줄(상의와 하의 경계). 없으면 엉덩이 높이로 추정.
- 소매: 팔 선을 따라가다 맨살이 나오는 곳까지. 겨드랑이 위는 진동 둘레선 바깥, 아래는 팔 둘레 띠.
- 착용 사진은 몸 앞면 폭만 보이므로 가로 배율 보정(`widthScale` 1.3)으로 넓게 펴서 입힌다.

## 5. 실전 확인 방법(접속 가능한 환경에서)

```bash
cd web && npm run build:ext
node tools/harness/ext.mjs "https://www.nike.com/kr/t/<상품>" /tmp/person.y4m /tmp/nike.png
node tools/harness/ext.mjs "https://www.adidas.co.kr/<상품>.html" /tmp/person.y4m /tmp/adidas.png
```

출력의 `수집된 후보`(주소 목록)와 `selected`(고른 사진), `fit`(사진별 평가)을 보고,
고해상도 주소가 404이면 `urls.ts`의 변환 인자를, 옷 사진이 목록에 없으면 `collectProductImages`를 고친다.
접속이 막힌 환경에서는 두 사이트 구조를 흉내 낸 시험 페이지(`tools/harness/fake-shop.mjs`)로 같은 흐름을 확인했다.

| 시험 페이지 | 흉내 낸 구조 | 결과 |
|---|---|---|
| 나이키형 | 대표 사진 = 모델 착용, 옷 사진은 지연 로딩(`data-src`)·썸네일, 아래에 추천 상품 | 후보 3장 수집(추천 상품 제외), 3번째 옷 사진 자동 선택 |
| 아디다스형 | JSON-LD 목록(모델 → 뒷면 laydown → 앞면 laydown), `<picture>` | 앞면 `_01_laydown`을 1순위로 수집·선택 |
| 모델 사진만 | 대표 사진만 모델 착용 | 모델 착용 사진 분석으로 상의를 잘라 입힘 |
