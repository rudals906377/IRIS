# 2026-10-12 개발일지

## 사진처럼 더 사실적으로: 헤어 모양·색과 메이크업을 전용 생성 모델로 옮기기

사용자 요청: "Anywear 처럼은 못 하지?" → "메이크업·헤어를 사진처럼 더 사실적으로 그려 주는 것".
실시간 합성(색·질감 덧입히기)의 한계를 넘기 위해 학교 GPU 서버에 전용 모델 두 개를 붙이는 세 번째 엔진 **"사진처럼"** 을 만들었다.

### 학교 GPU 실사용과 "실시간에 입히기"
- 학교 PC 설치 중 막힌 것: 한글 윈도우 cp949 로 FaceLib 설치 파일이 깨짐(→ 파이썬 UTF-8 모드), huggingface_hub 버전 충돌(→ 조건 제거), 깃허브 raw 캐시로 새 파일이 안 받아짐(→ update.py 에 꼬리표·no-cache), Hugging Face 도구가 윈도우에서 멈춤(→ 직접 주소로 이어받기). 설치 뒤 세 서버 연결 확인(`realistic: {hair, makeup}`)
- GPU 에서 헤어 첫 요청이 `KeyError 'ACE'`: 저장소가 평균 스타일 코드를 현재 폴더 기준 상대 경로로 읽는데 요청 처리 때 다른 폴더였다(CPU 는 그 분기를 안 타서 통과) → 요청 처리 중 저장소 폴더로 들어감
- 사용자 질문 "라이브에서는 못 해?": 완전 실시간 생성은 장비·품질 모두 안 됨 → **한 번 생성 → 실시간으로 따라오게**: 메이크업은 생성 결과(내 얼굴에 그 화장)를 사진 따라하기에 넣어 실시간 화장으로(내 피부 기준이라 남의 사진보다 정확), 헤어는 생성된 머리카락만 오려 얼굴 윤곽·콧대 점의 닮음 변환으로 따라다니는 스티커(엔진에 2D 오버레이 그리기 훅 추가, 📸 저장에도 포함, 칩 "헤어(생성)")

### 맥북 실사용에서 나온 것
- ✨ AI 생성 단추가 안 보임: 서버 확인이 주소를 넣을 때 한 번만 → 붙여넣는 즉시(input)·숨어 있는 동안 15초마다 다시 확인
- 금발 염색이 노란 페인트처럼 평평하고 분할이 얼룩짐: ① 실험용 자체 머리카락 모델 체크가 localStorage 에 남아 계속 켜져 있었다 → 저장하지 않고 켤 때만. ② 셰이더가 결 압축(kc)을 가는 올까지 눌렀다 → 큰 명암에만 압축, 올은 0.8 이상 유지, 밝게 올릴수록 밝은 결은 흰빛으로(탈색 윤기). 평가 55쌍 색오차 5.18→5.21·결오차 동일(회귀 없음)

### 문제와 해결
- 클라우드에 GPU 가 없어 CPU 로 검증: 두 저장소 모두 코드 곳곳에 `cuda` 가 박혀 있어 `cpu_patch.py`(torch.load·.cuda()·.to('cuda')·텐서형 문자열·cuda.is_available·정수 nearest 보간 우회)로 돌렸다. 학교 GPU 에서는 쓰지 않는다. 두 모델 모두 끝까지 돌아 결과 그림을 확인했다
- 디스크가 가득 차 가중치가 끊김 → 캐시 정리. 두 모델을 동시에 돌리자 메모리(15GB)를 넘어 둘 다 죽음 → 차례로
- torch hub 가 받은 resnet18 이 디스크 부족으로 잘려 "unpickling stack underflow" → 지우고 다시

### 결정 사항
- 네일·타투는 기존 엔진(기본·AnyDoor) 그대로, 헤어·메이크업만 "사진처럼" 엔진
- 메이크업 결과에는 색감 맞추기(harmonize)를 쓰지 않는다(화장 색을 되돌림)
- 품질 루프(매일 자동)는 사용자 요청으로 꺼 둠
