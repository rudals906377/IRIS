# 2026-10-06 개발일지

## 학교 GPU 에서 AnyDoor 실사용 + 맥북 원격 사용 흐름 완성

사용자가 학교 PC(RTX 3080 10GB)에서 설치·실행하고 맥북 웹 앱으로 쓰는 하루. 설치부터 첫 합성까지 막히는 곳을 하나씩 풀었고, 실제 사용 캡처로 실시간 염색·타투 자리·참고 도안 찾기의 문제를 잡았다.

### 한 일
| 항목 | 내용 |
|---|---|
| 설치 스크립트 | 한글이 든 `.bat` 이 PC 마다 깨져(명령으로 오해) 설치가 안 됨 → 설치·실행 논리를 파이썬(`setup.py`, `tunnel.py`, `run.py`)으로 옮기고 `.bat` 은 ASCII 한 줄 래퍼. AnyDoor 설치는 git 없이도(ZIP), 9.4GB 가중치는 끊겨도 이어받기. `update.py` 가 AnyDoor 폴더까지 갱신 |
| AnyDoor 패키지 | 파이썬 3.11: `transformers 4.19` 가 요구하는 `tokenizers 0.12` 는 미리 빌드가 없어 Rust 컴파일 실패 → `transformers>=4.30`, `timm 0.9`(0.6.12 는 3.11 에서 import 오류), `torchmetrics 0.6.0`. 여기(파이썬 3.11, CPU torch 2.0.1)에서 cldm/ldm import 와 모델 생성까지 확인 |
| AnyDoor 저메모리 | 실제 호출에서 `cuda:0 and cpu` 오류 → DDIM 샘플러가 `model.betas.device` 에 잡음을 만드는데 저메모리 모드에서 본체 버퍼가 CPU 에 남아 있었음. 본체 버퍼만 GPU 로. CPU 모사로 compose 전체 경로 검증 |
| 작업 번호 방식 | 무료 터널(trycloudflare)은 100초 넘는 응답을 끊음(524) → `POST /generate/start` → `GET /job/{id}` 2초 폴링. 웹은 경과 초·서버 로그 표시, 옛 서버면 예전 방식 |
| 기본 엔진 버그 | `GenRequest.color_fn` 에 타입 표기가 없어 dataclass 필드로 안 잡힘 → 기본 엔진(SDXL) 요청이 모두 실패하던 것 수정(시험 서버로 발견) |
| 실시간 염색 | 확률 5% 픽셀까지 칠해 밝은 색일 때 이마에 계단 모양 밝은 띠 → 12% 아래는 손대지 않음. 가이디드 필터 계수를 주변 4점과 평균해 잔머리 경계의 점점이 얼룩 완화 |
| 타투 자리 | 팔이 안 보이면 몸 피부 전체로 대체해 머리를 다시 그림 → 자세 점의 보임 확률·화면 안 여부 확인, 못 찾으면 부위별 안내 문구(422). 얼굴 피부는 항상 제외, 자리 0.3% 미만 거절 |
| 참고 도안 찾기 | "어둡고 무채색 가장 큰 덩어리" 가 검은 어깨끈을 타투로 골라 목에 끈을 합성(실제 결과) → 피부 위 국소 대비 잉크 + 새까만 큰 덩어리 제외 + 흩어진 도안을 4% 넓혀 묶고 볼록 껍질. 나비 2마리+별 사진과 시험 사진 6장에서 확인 |

### 문제와 해결
- `.bat` 더블클릭 금지 정책 + CP949/UTF-8 혼선 → 파이썬으로 일원화하니 PC 가 바뀌어도 같은 명령(`python setup.py`)으로 끝
- 자체 학습 머리카락 모델을 켜면 머리카락 확률이 거의 안 잡혀 얼룩덜룩 칠해짐(시험 환경에서 켬/끔 확률 지도 비교로 확인). 당장은 끄도록 안내, 원인(웹캠 머리 잘라내기와 학습 분포 차이로 추정)은 다음에
- 깃허브 raw 캐시로 `update.py` 가 새 파일을 늦게 받음 → 두 번 실행 안내

### 결정 사항
- 설치·실행은 파이썬 스크립트가 기준, `.bat` 은 편의용 래퍼
- 원격 사용은 작업 번호 방식이 기본(100초 제한과 무관)
- 자체 헤어 모델은 기본 꺼짐 유지, 원인 규명 전까지 권하지 않음

### AI 도구 활용
- Claude Code: 캡처 기반 원인 추적(서버 로그·시험 환경 재현·확률 지도 덤프), 파이썬 3.11 환경에서 AnyDoor 의존성 재현, CPU 모사로 GPU 코드 경로 검증, 터널로 실제 GPU 서버 호출 시험
