# 2026-10-14 개발일지

## 생성 머리를 더 자연스럽게: 3D 로 따라오기 · 헤어 2(Stable-Hair) · 긴 머리 이어 그리기

사용자 질문에서 출발: "지금 그래픽카드로는 이게 한계야?" → "Anywear(https://anywear.decart.ai) 정도 품질을 내고 싶다" → "무료 모델로는 지금이 최대치야?"
조사 결과 Anywear 는 Decart 의 비공개 실시간 영상 생성 모델(Lucy)을 자사 서버에서 돌리는 방식이라 공개 모델·학교 GPU 로는 같은 방식이 불가능하고,
같은 품질은 Decart API(실시간 720p 초당 $0.02)로만 가능하다고 정리했다. 무료로 올릴 수 있는 여지(① 실시간 붙이기 추적, ③ 섞는 자리, ② 헤어 모델)를 순서대로 진행했다.

### 오늘 한 일
| 항목 | 내용 |
|---|---|
| ▶ 실시간에 입히기 3D | 캡처 때와 지금의 얼굴 점(깊이 포함, 깊이는 가볍게 평균)으로 **3D 닮음 변환**(Horn 사원수 방법, `head-warp.ts`)을 구하고, 머리 사진 격자 32×32 에 **머리 타원체 깊이**(앞면이 이마 점을 지나도록 맞춤, 타원 밖 늘어진 머리는 머리 중심 깊이의 평면)를 줘서 지금 자세로 투영한다. 작은 WebGL2 그리기 도구(`sticker-gl.ts`)로 격자를 휘어 그림. 돌릴수록 얼굴 자리(눈썹 아래 윤곽)를 부드럽게 지워 먼 쪽 머리가 얼굴을 덮지 않게, 35~55° 에서 서서히 사라짐. 깊이·WebGL2 가 없으면 예전 평면 스티커 |
| 헤어 2: Stable-Hair | 내 머리를 먼저 지우고(Bald Converter) 고른 사진의 머리를 새로 그리는 디퓨전 모델(Apache-2.0, SD1.5 기반). Stable-Makeup 과 각자 고친 diffusers 사본이 달라 한 프로세스에 못 올림 → `stablehair_server.py`(8768)로 따로 띄우고 `run.py` 가 함께 켬. 얼굴 정렬·되붙이기는 기존 `face_align`, SD1.5 는 메이크업과 공용, 10GB 카드용으로 단계마다 필요한 모델만 GPU 에 올림, GPU 메모리 부족은 안내 문구. 설치 스크립트에 가중치 6.1GB(공식 Google Drive) 추가(다시 실행하면 이것만 받음) |
| 헤어 모델 선택 | 생성 서버 `hair_model`(auto·hairfast·stablehair): 자동은 HairFastGAN, **고른 사진에서 얼굴을 못 찾으면 헤어 2 로 다시**. 웹 ✨ 고급에 "헤어 모델(자동·빠르게·다시 그리기)" |
| 정렬 사각형 직선 | 섞는 가중치에 사각형 안쪽 페이드(`inner_fade`, 사진 테두리 쪽은 깎지 않음) → 머리 위쪽에 보이던 사선 자국이 부드럽게 |
| 긴 머리 잘림 | 사용자 피드백 "긴 머리 사진도 하단이 잘려서 나온다". 원인: 헤어 모델은 얼굴에 맞춘 정사각형(정수리 위~턱 아래 조금) 안만 그린다. `hair_extend.py`: 고른 사진의 머리 길이(턱 아래로 얼굴 길이 몇 배)를 재고, 모델이 그린 머리가 사각형 아래 끝에 닿은 다발을 그 길이까지 U자 끝(가운데 길고 바깥 짧게, 굵은 갈래로 들쭉날쭉)으로 늘린 마스크 → 위 머리를 아래로 늘여 깔고 SD1.5 인페인팅(0.75, CPU 오프로드)으로 결·끝만 다시 그림, 색은 위에 그려진 머리에 맞춤. 실패하면 잘린 채로 둠 |
| 사용자 안내 | 학교 PC cmd 사용법을 처음부터(창 1 사진처럼 서버, 창 2 생성 서버, 창 3 터널, 맥북 설정) 다시 정리. 생성 서버 준비 표시는 `IRIS 생성 서버: ... (dry-run=False)` 줄 |

### 문제와 해결
- 3D 붙이기 시험: 고개 돌리는 영상(male-turn.webm)의 정면 장면을 찍어 줄무늬 가짜 머리를 만들고 장면마다 3D·평면을 나란히 저장(`tools/eval/sticker3d.mjs`). 처음 8초는 정면뿐이라 영상 전체(33초)로 넓힘. 반쯤 돌린 장면에서 평면 스티커는 머리가 배경 쪽으로 미끄러지고, 3D 는 머리를 감싸며 붙음. 옆얼굴에 가까우면 3D 는 사라지고 평면은 얼굴 위에 엉뚱하게 남음
- Stable-Hair CPU 검증: 전부 fp32 면 UNet 세 벌로 메모리 14GB → 이 클라우드 CPU 가 AMX bf16 을 지원해 bf16 으로(약 7~9GB, 단계당 6초). 저장소가 참고 머리 특징을 fp16 으로 고정해 bf16 에서 "expected Float but found BFloat16" → 모델 정밀도를 따르게 실행 중 바꿔 끼움. 처음부터 쓸 정밀도로 불러 메모리 최고점도 줄임
- 자동 대체 시험: "고른 사진에서 얼굴을 못 찾음"만 답하는 가짜 HairFastGAN 서버 + 실제 Stable-Hair + 생성 서버로 끝까지 → 로그 "고른 사진에서 얼굴을 못 찾음 → 헤어 2 로 다시", 머리카락 자리만 섞이고 얼굴은 원래대로
- 긴 머리 이어 그리기를 다섯 번 고침: ① 네모난 마스크라 어깨에 로고 같은 무늬가 그려짐 → 끝 모양을 둥글게·부정 문구(logo, emblem, text…) ② 한쪽은 머리 대신 옷이 그려짐 → 위 머리를 늘여 미리 깔고 0.75 로만 다시 그림 ③ 여전히 한쪽이 안 늘어남 → 섞은 결과는 사각형 가장자리에서 원래 사진(짧은 머리)으로 돌아가 머리를 못 찾은 것, 모델이 그린 그대로에서 다발을 찾고 색을 가져오게 ④ 위쪽에 어두운 띠 → 늘리는 자리를 사각형 페이드 띠 위에서 시작 ⑤ 이음매 밝기 차이 → 색을 고른 사진이 아니라 위에 그려진 머리에 맞춤
- 빠른 반복을 위해 HairFastGAN 결과를 저장해 두고 그대로 돌려주는 가짜 서버로 생성 서버만 다시 돌림(2.5분 → 생략)

### 결정 사항
- Anywear 수준(매 프레임 영상 생성)은 무료 모델·학교 GPU 로는 안 함. 원하면 Decart API 를 엔진으로 붙이는 안을 남겨 둠(영상이 외부로 나가므로 개인정보 문구 변경 필요)
- 헤어 기본은 HairFastGAN 유지: 같은 얼굴·참고 3쌍 비교에서 Stable-Hair 와 품질이 비슷했고 HairFastGAN 이 더 매끈(분홍 단발의 풍성함도 더 잘 살림). Stable-Hair 는 얼굴 없는 사진 대체와 직접 선택용
- 긴 머리 이어 그리기는 기본으로 켬(고른 사진 머리가 턱 아래 0.6배 미만이거나 결과가 사각형 끝에 안 닿으면 자동으로 건너뜀)

### AI 도구 활용
- Claude Code: Anywear·Decart API 조사(요금·입력·지원 범위), 3D 자세 수학(Horn 사원수·타원체 깊이)과 단위 테스트, WebGL2 격자 휘기, Stable-Hair 코드 읽기와 별도 서버화·CPU bf16 우회, 가짜 서버로 대체 경로 끝까지 시험, 긴 머리 이어 그리기 반복 수정(결과 그림을 보고 원인 진단)
