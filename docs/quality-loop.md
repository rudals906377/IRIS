# 품질 개선 루프 (매일 자동)

목표: 고른 사진이 사용자에게 **정확하게**(색·위치가 사진과 같게) **자연스럽게**(경계·결·떨림 없이) 입혀지도록, 점수를 재고 가장 나쁜 것을 고치는 일을 매일 되풀이한다.
사람 손을 타지 않는 범위에서만 바꾸고, **점수가 좋아질 때만 남긴다.**

## 한 회차 순서

1. 준비: `git pull`, `cd web && npm ci && npm run build`, 시험 자료가 없으면 `bash tools/harness/fetch-testdata.sh`.
   미리보기 서버는 따로 띄우면 셸이 끝날 때 같이 죽는다. **평가 명령과 같은 셸 안에서** 띄우고 끝나면 끈다:
   `tools/eval/with-preview.sh node tools/eval/makeup.mjs 기준 testdata/face/00055_00.webm 21`
   (머리카락 평가 자료 `web/public/testdata/eval/hair/` 가 없으면 머리카락 항목은 건너뛴다. 만드는 법은 tools/eval/README.md)
2. 기준 점수: `tools/eval/README.md` 기록 표의 마지막 줄이 기준. 없으면 먼저 한 번 재서 기록한다.
   - 사진 따라하기: `node tools/eval/makeup.mjs 기준 testdata/face/00055_00.webm 21` (약 25분)
   - 염색: `node tools/eval/haircolor.mjs 기준`
   - 머리카락 영역: `node tools/eval/hair.mjs 기준 '{}'`
3. 과녁 고르기: 결과 JSON(`tools/eval/results/`)에서 **가장 나쁜 사진 1~2장**을 고른다.
   `tools/harness/photocheck.mjs` 또는 `window.irisPhoto.check()` 로 사진 측정값·결과 측정값·되먹임 기록을 보고 **왜** 틀리는지 먼저 적는다(측정 오류인지, 되먹임이 못 따라가는지, 합성이 못 내는 색인지).
4. 한 가지만 고친다. 고친 뒤 **같은 자료로 다시 재서** 전체 평균이 나빠지지 않고 과녁이 좋아졌을 때만 남긴다. 나빠지면 되돌리고 그 사실을 기록에 남긴다(같은 시도를 반복하지 않게).
5. 통과 조건: `npm test`, `node tools/harness/smoke.mjs`, 빌드. 데스크톱·휴대폰 캡처로 화면이 깨지지 않았는지 본다.
6. 기록: `tools/eval/README.md` 기록 표에 한 줄, 개발일지(`docs/devlog/<날짜>.md`)에 "품질 루프" 절. 커밋 메시지는 한국어, 푸시는 `git push -u origin claude/virtual-try-on-realtime-7uwjlm`.

## 규칙

- 평가가 도는 동안 `npm run build` 하지 않는다(dist/testdata 가 지워져 평가가 멈춘다).
- 저작권 있는 사진·가게 사진은 절대 커밋하지 않는다. 시험 자료는 `web/public/testdata/`(gitignore) 에만.
- 하루 한 회차에 바꾸는 것은 한두 가지. 수치 없이 "느낌"으로 바꾸지 않는다.
- 학교 GPU 가 필요한 것(자체 머리카락 모델 전체 학습, 네일 모델)은 루프가 하지 않고 "사용자가 할 일"로 적어 둔다.
